# Purpose

## 실행 단위

- 한 번 실행할 때 프로젝트(웹 콘텐츠) 1개의 게시물 에셋 한 벌을 만든다.
- 인자 `project`는 projects.yaml에 등록된 값만 허용한다 (예: `my-project`). 등록 항목에 주소, `<title>`, 대상 종류, 쓰기 허용 여부, 요청 사항(에셋 수 등)을 적는다.
- 모든 프로젝트가 같은 SSOT 파일 `rules.yaml`을 읽는다.

## 사용자

- 실행·검토·승인은 작업자 1명이 한다 (디자이너·개발자 등 웹 콘텐츠를 만든 사람).
- 결과 에셋은 같은 사람이 게시 문구를 쓰고 인스타그램에 올릴 때 쓰는 입력 파일이다.

## 범위

- story-work.md의 2~14단계를 포함한다 (1단계 설치는 README "처음 준비하기").
- 하네스는 게시할 에셋 파일(이미지 PNG, 영상 MP4)을 `runs/<project>/export/`에 만드는 데까지만 한다. 게시 문구와 게시는 하지 않는다 (경계 B3에서 멈춤).
- Figma를 쓰지 않는다. 피드 분석·레퍼런스 조사·배경색 겹침 검사를 하지 않는다.
- 로그인이 필요한 웹 콘텐츠는 지금 다루지 않는다.

## 완료 기준

- 에셋 수가 rules.yaml `assets.count`(프로젝트 요청이 있으면 그 값) 범위 안이다.
- 모든 에셋이 rules.yaml `assets.canvas` 크기이고 `export` 규격과 맞는다.
- 모든 게이트가 PASS이고, 사람이 촬영 계획과 완성본을 각각 승인했다.

## 사용자가 정한 것 (2026-09-30)

- 캔버스 1080x1440 (3:4). 녹화는 360x640에 배율 3 (1080x1920).
- 이미지는 화면 1~3개로 구성할 수 있고, 영상은 화면 1개만.
- 에셋 5~10개, 영상 20초 이하 (별도 요청이 없을 때).
- 사람 승인은 2번: 촬영 계획(에셋 목록 + 녹화본), 완성본.
- 녹화 대상은 배포 URL과 로컬 dev 서버 둘 다.
- 배경색은 사람이 검토용 HTML에서 고른다. 자동 검사는 "모든 에셋의 배경이 같은 색인가"만 한다.
- 검토용 HTML은 로컬 서버로 연다. 구간·속도·배경색 등을 고치고 "내보내기"로 결과를 다시 본다.
- 우선 인스타그램 기준. 다른 규격은 나중에 넓힌다.
- 첫 실제 프로젝트로 녹화부터 내보내기까지 검증했다 (2026-10-01).
