## 화면에서 승인했는데 다음 단계로 가지 않아요

**원인**: 화면 버튼은 승인·거절을 기록만 해요. AI는 Claude Code에서 일하고, 버튼을 기다리지 않아요.

**해결**: Claude Code에 `<프로젝트> 이어서 해줘`라고 말해요. 시작 화면의 **지금 할 일**에도 같은 문장이 나와요.

## 편집했는데 mp4가 그대로예요

**원인**: 편집 내용은 `edits.json`에만 저장되고, 파일은 다시 만들기 전까지 그대로예요. 화면 위쪽 "파일 미반영 N개"나 에셋의 "수정됨" 표시가 그 상태예요.

**해결**: 오른쪽 위 **내보내기**를 눌러요. "✓ 파일에 모두 반영됨"으로 바뀌면 끝이에요.

## 시작 화면 1단계에 빠진 도구가 나와요

**원인**: 필요한 도구가 없거나 설치가 덜 됐어요. 화면(또는 `npm test`의 "실행 환경 FAIL")에 빠진 항목이 나와요.

**해결**: 해당 항목을 설치한 뒤 시작 화면 오른쪽 위 **다시 확인**을 눌러요.

```bash
npm install                       # 녹화 엔진 등 패키지
brew install ffmpeg               # ffmpeg (macOS)
npx playwright install chromium   # 녹화용 브라우저
```

## 목록·본문이 비어 있는 채로 녹화돼요

**원인**: 녹화할 때 사이트에 기록이 남지 않게 저장 요청(POST 등)을 막아요. 그런데 데이터를 읽을 때도 POST를 쓰는 사이트가 있어요. Firestore 읽기와 Algolia 검색은 기본으로 통과시키지만, 그 밖의 백엔드는 막힐 수 있어요.

**해결**: AI가 막힌 주소와 통과시킬 규칙을 알려 줘요. 읽기 요청이 맞으면 `projects.yaml`의 그 프로젝트에 `allow_post`를 적고 `<프로젝트> 이어서 해줘`라고 말해요 ([설정](configuration.md)).

```yaml
  my-site:
    url: https://example.com
    allow_post: ["api\\.example\\.com/graphql"]
```

## Claude Code가 명령마다 실행 허락을 물어요

**원인**: 두 가지예요.

- 폴더를 신뢰하지 않으면 저장소에 미리 적어 둔 허용 목록이 적용되지 않아요.
- 말로 승인·거절할 때 쓰는 기록 명령은 사람이 직접 확인하도록 **일부러** 허용 목록에서 뺐어요.

**해결**: 처음 `claude`를 실행할 때 폴더 신뢰를 **Yes**로 골라요. 승인·거절 때 뜨는 허락 창은 허용을 누르면 돼요. 시작 화면의 승인·거절 버튼을 쓰면 묻지 않아요.

## 녹화된 조작이 느리거나 스크롤이 기계 같아요

**원인**: AI가 정한 조작 간격과 스크롤 방식이 의도와 달라요.

**해결**: 녹화 확인 화면에서 고칠 점을 적고 **거절하고 다시 찍기**를 누른 뒤, Claude Code에 `<프로젝트> 이어서 해줘`라고 말해요. 다시 찍은 녹화본은 이전 녹화본과 나란히 비교할 수 있어요.

```text
버튼 사이 간격을 절반으로, 스크롤은 사람처럼
```

이미 편집 단계라면 편집 화면에서 재생 속도(0.8x~2.0x)를 올려요. 재생 속도는 화면 애니메이션까지 함께 빨라지니, 간격만 줄이려면 다시 찍는 쪽이 자연스러워요.

## 하네스가 STOP으로 멈췄어요

**원인**: 셋 중 하나예요.

- 거절이나 자동 검사 실패가 `rules.yaml`의 `retry` 횟수를 넘었어요.
- 거절했는데 AI가 아무것도 바꾸지 못했어요.
- 실행 환경에 문제가 있어요.

**해결**: 시작 화면의 멈춘 단계(빨간 표시)에 이유가 나와요. 원인을 고친 뒤 Claude Code에 `<프로젝트> 계속 진행해`라고 말해요. 편집 단계라면 편집 화면에서 직접 고치고 내보내기를 눌러도 돼요.

```bash
npm run status -- <프로젝트>   # 터미널에서 볼 때: "reason"에 멈춘 이유가 나와요
```
