## 명령줄에서 Claude Code를 찾을 수 없다고 나와요

**원인**: 명령줄은 AI 단계를 Claude Code(`claude`)에 맡겨요. 설치되지 않았거나 PATH에 없어요.

**해결**: 설치하고 한 번 실행해 로그인한 뒤 같은 명령을 다시 실행해요.

```bash
npm install -g @anthropic-ai/claude-code
claude          # 로그인 후 /exit
npx ai-url-to-feed stuckyi.studio
```

## 명령줄이 세 번 이어서 했지만 끝나지 않았다고 나와요

**원인**: Claude Code가 완성 전에 끝나는 일이 세 번 이어졌어요. 허용되지 않은 명령을 쓰려다 막혔거나, 사이트가 응답하지 않는 경우가 많아요.

**해결**: `runs/.harness/log/<프로젝트>-claude.log`의 마지막 부분에 Claude Code가 남긴 이유가 있어요. `npx ai-url-to-feed status <프로젝트>`로 멈춘 단계를 보고, 원인을 고친 뒤 같은 명령을 다시 실행하면 그 단계부터 이어서 해요.

## 진행 막대가 한참 그대로예요

**원인**: 대개 정상이에요. 장면 계획(1/5)은 AI가 사이트를 둘러보고 시나리오를 미리 돌려 보느라 몇 분 걸려요. 그동안 막대 칸은 그대로이고, 오른쪽 "화면 N개 둘러봄 · 시나리오 N번 돌려 봄"과 시간이 늘어요. 이 숫자가 늘고 있으면 진행 중이에요.

**확인**: 다른 터미널에서 `tail -f runs/.harness/log/<프로젝트>-claude.log`로 Claude Code가 남기는 기록을 봐요. 30분이 넘도록 그대로면 Ctrl+C로 멈추고 같은 명령을 다시 실행해요. 멈춘 단계부터 이어서 해요.

## 화면에서 승인했는데 다음 단계로 가지 않아요

**원인**: 화면 버튼은 승인·거절을 기록만 해요. AI는 Claude Code에서 일하고, 버튼을 기다리지 않아요.

**해결**: 같은 명령(`npx ai-url-to-feed <주소>`)을 다시 실행하거나, Claude Code에 `<프로젝트> 이어서 해줘`라고 말해요. 시작 화면의 **지금 할 일**에도 같은 문장이 나와요.

## 편집했는데 mp4가 그대로예요

**원인**: 편집 내용은 `edits.json`에만 저장되고, 파일은 다시 만들기 전까지 그대로예요. 상단 바 제목 아래 "파일 반영 전 N개"나 에셋의 "수정됨" 표시가 그 상태예요.

**해결**: 오른쪽 위 **내보내기**를 눌러요. "파일에 모두 반영됨"으로 바뀌면 끝이에요.

## 빠진 도구가 나와요

**원인**: 필요한 도구가 없거나 설치가 덜 됐어요. 명령줄은 "실행 환경을 먼저 준비해야 해요" 아래에, 시작 화면은 맨 위 안내에(또는 `npm test`의 "실행 환경 FAIL") 빠진 항목이 나와요.

**해결**: 해당 항목을 설치한 뒤 같은 명령을 다시 실행해요 (시작 화면은 오른쪽 위 **다시 확인**).

```bash
npm install                       # 녹화 엔진 등 패키지
brew install ffmpeg               # ffmpeg (macOS)
npx playwright install chromium   # 녹화용 브라우저
```

## 목록·본문이 비어 있는 채로 녹화돼요

**원인**: 녹화할 때 사이트에 기록이 남지 않게 저장 요청(POST 등)을 막아요. 그런데 데이터를 읽을 때도 POST를 쓰는 사이트가 있어요. Firestore 읽기와 Algolia 검색은 기본으로 통과시키지만, 그 밖의 백엔드는 막힐 수 있어요.

**해결**: AI가 막힌 주소와 통과시킬 규칙을 알려 줘요. 읽기 요청이 맞으면 `projects.yaml`의 그 프로젝트에 `allow_post`를 적고 같은 명령(`npx ai-url-to-feed <주소>`)을 다시 실행해요. 이미 완성까지 갔다면 `npx ai-url-to-feed retake <프로젝트> "목록이 보이게 다시 찍기"`로 다시 찍어요 ([설정](configuration.md)).

```yaml
  my-site:
    url: https://example.com
    allow_post: ["api\\.example\\.com/graphql"]
```

## Claude Code가 명령마다 실행 허락을 물어요

**원인**: 두 가지예요.

- 폴더를 신뢰하지 않으면 저장소에 미리 적어 둔 허용 목록이 적용되지 않아요.
- 말로 승인·거절할 때 쓰는 기록 명령은 사람이 직접 확인하도록 **일부러** 허용 목록에서 뺐어요.

**해결**: 처음 `claude`를 실행할 때 폴더 신뢰를 **Yes**로 골라요. 승인·거절 때 뜨는 허락 창은 허용을 누르면 돼요. 시작 화면의 승인·거절 버튼을 쓰면 묻지 않아요.

## 녹화된 조작이 느리거나 스크롤이 기계 같아요

**원인**: AI가 정한 조작 간격과 스크롤 방식이 의도와 달라요.

**해결**: 시작 화면의 **녹화 원본 보기**(꼼꼼 모드는 녹화 확인)에서 해당 장면 옆 말풍선 버튼으로 메모를 남기거나 "조작을 더 빠르게" 같은 빠른 선택을 누르고 **메모 보내고 다시 찍기**를 누른 뒤, Claude Code에 `<프로젝트> 이어서 해줘`라고 말해요. 명령줄에서는 `npx ai-url-to-feed retake <프로젝트> "조작을 더 빠르게"` 한 줄이면 돼요. 다시 찍은 녹화본은 "이전 녹화와 비교"에서 나란히 볼 수 있어요.

```text
버튼 사이 간격을 절반으로, 스크롤은 사람처럼
```

이미 편집 단계라면 편집 화면에서 재생 속도(0.8x~2.0x)를 올려요. 재생 속도는 화면 애니메이션까지 함께 빨라지니, 간격만 줄이려면 다시 찍는 쪽이 자연스러워요.

## 녹화 영상이 20초보다 길어요

**원인**: 녹화 원본 화면에 나오는 영상은 게시물의 **재료**인 녹화 원본이에요. 원본은 한 흐름을 이어 찍어 30초가 넘을 수 있어요 (최대 `record.max_raw_seconds`, 기본 120초).

**확인**: 게시물 영상(`runs/<프로젝트>/export/*.mp4`)은 게시물 만들기 단계에서 원본의 필요한 구간만 잘라 만들고, 자동 검사가 `max_video_seconds`(기본 20초)를 넘으면 실패로 막아요. 결과 보기(완성본 확인) 화면에 영상마다 길이가 나와요.

## 하네스가 STOP으로 멈췄어요

**원인**: 셋 중 하나예요.

- 거절이나 자동 검사 실패가 `rules.yaml`의 `retry` 횟수를 넘었어요.
- 거절했는데 AI가 아무것도 바꾸지 못했어요.
- 실행 환경에 문제가 있어요.

**해결**: 명령줄의 "멈췄어요" 아래(또는 `npx ai-url-to-feed status <프로젝트>`), 시작 화면의 멈춘 단계(빨간 표시)에 이유가 나와요. 원인을 고친 뒤 `npx ai-url-to-feed continue <프로젝트>`를 실행해요 (대화로 진행 중이면 Claude Code에 `<프로젝트> 계속 진행해`). 편집 단계라면 편집 화면에서 직접 고치고 내보내기를 눌러도 돼요.

```bash
npx ai-url-to-feed status <프로젝트>   # 단계별 상태와 멈춘 이유
```
